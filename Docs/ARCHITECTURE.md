# Architecture

## 목적

이 문서는 AI 에이전트가 파일을 만들거나 이동할 때 폴더 책임, 파일 배치, Aeterna 공통 시스템과 상태 소유권을 확인하는 기준 문서입니다.

## 구조 원칙

- Unreal C++ 코드, Blueprint 자산, 맵, UI, 데이터, 문서 책임을 분리합니다.
- 지금 필요한 task 범위에서만 구조를 확장하며, 계획에 있다는 이유만으로 빈 폴더나 미사용 구조를 미리 만들지 않습니다.
- 시스템의 책임을 먼저 정하고 C++ 클래스, Actor, Component, Subsystem, Blueprint 같은 구체 구현 형태는 현재 task에서 승인된 범위로 결정합니다.
- 프로젝트 기획 불변 조건은 `AGENTS.md`의 `Aeterna 기획 기준`(§3)을 따릅니다. 그 원본은 `Docs/GDD_v1.3_에테르나.md`이며, **이 문서와 GDD가 충돌하면 GDD가 우선합니다.**
- 파일과 자산의 이름 규칙은 `Docs/STYLEGUIDE.md`와 `AGENTS.md` §4-2를 따릅니다.

## 공통 폴더 책임

- `Docs/`: 하네스 문서와 작업 규칙
- `Tasks/`: 개별 task 문서와 task 작성·요청 양식
- `Source/`: C++ 코드
- `Content/`: Blueprint, 맵, UI, 애니메이션, 모델, 머티리얼, 오디오 등 Unreal 자산

## Aeterna 초기 상태

하네스 초기화 시점에는 `AGENTS.md`, `Docs/`, `Tasks/`만 확정되어 있습니다. Unreal 프로젝트와 실제 `Source/`, `Content/` 구조는 첫 구현 task에서 현재 저장소 상태를 확인한 뒤 기록합니다.

- 현재 확정된 Unreal 코드 파일: 없음
- 현재 확정된 Unreal 자산: 없음
- 현재 확정된 플레이 맵: 없음

## 생성 시 사용할 책임 경계

아래 경로는 해당 책임이 실제 task에서 필요하고 생성 승인을 받은 뒤 사용합니다. 경로 자체를 선제 생성하라는 의미가 아닙니다.

- `Source/Aeterna/`: Aeterna 게임 모듈의 C++ 코드
- `Content/Aeterna/Maps/`: 경비실과 박물관 구역을 포함한 플레이 가능한 맵 자산
- `Content/Aeterna/Blueprints/Player/`: M-05 플레이어, 헤드램프, 스캔 상호작용 Blueprint
- `Content/Aeterna/Blueprints/Core/`: 여러 밤이 공유하는 진행 제어·공용 상호작용 Blueprint
- `Content/Aeterna/Blueprints/Scenario/S01/`~`S03/`: 특정 밤에서만 사용하는 Actor와 상호작용 Blueprint
- `Content/Aeterna/UI/`: 수첩, 시계, 배터리 게이지, 상호작용 프롬프트, 시스템 로그, 「Day N」 카드 위젯
- `Content/Aeterna/Data/`: 규칙·시각 이벤트·조명 ID·실패 조건 DataTable과 임포트 CSV
- `Content/Aeterna/Audio/`: 환경음, 이상 현상 오디오, 시스템 로그 SFX
- `Content/Aeterna/VFX/`: 연출용 이펙트

폴더 이름은 `AGENTS.md` §6 디렉터리 구조를 그대로 따릅니다. 단수·복수를 임의로 바꾸지 않습니다.

## 공통 시스템 책임

아래 이름은 책임을 설명하는 개념명입니다. 실제 Unreal 클래스 종류와 파일명은 구현 task에서 결정합니다.

> 밤(시나리오) 1개 = 게임 내 01:00~05:00 전체입니다. **하룻밤을 시간 슬롯으로 쪼개지 않습니다.**

### ScenarioManager

- 현재 밤을 DataTable에서 로드하고 시작·클리어·게임 오버·재시작 상태를 관리합니다. 시나리오 목록을 하드코딩하지 않습니다 (GDD §11-3).
- **밤 시작 시에만** 경비실 스폰을 조정합니다.
- 밤 클리어 시 완료 지점에서 페이드아웃 → 「Day N」 카드 → 다음 밤 경비실 재기동으로 전환합니다. **클리어 후 경비실로 돌아가는 이동 로직을 만들지 않습니다** (GDD v1.3에서 폐기).
- 게임 오버 시에는 해당 밤을 처음부터, 즉 경비실 재기동으로 되돌립니다.
- 개별 이상 현상 Actor가 전체 시나리오 전환을 직접 소유하지 않게 합니다.

### GameClock

- 01:00부터 05:00까지의 게임 시간 진행과 배속을 관리합니다.
- **특정 시각 이벤트를 브로드캐스트합니다** (밤2: 01:44 / 02:44 / 03:44 / 04:44, 밤3: 03:03). 고정 간격 슬롯 경계가 아니라 시나리오 데이터에 정의된 시각 목록을 기준으로 합니다.
- 밤 재시작 시 시작 시각(01:00) 복구를 한 책임에서 제공합니다.

### NotebookRules

- 현재 밤의 수첩 규칙과 업무 목표를 DataTable에서 읽어 표시하고, 재시작 시 다시 제공합니다.
- 현장에서 스캔으로 획득하는 추가 수칙의 필사 상태를 관리합니다.
- 규칙의 문구와 순서는 승인된 시나리오 기획을 그대로 사용합니다.
- 위반 판정에 필요한 조건을 FailureSystem에 제공합니다.

### FailureSystem

- 수첩 규칙 위반을 감지하고 실패 연출과 재시작 요청을 연결합니다.
- **게임 오버 경로는 수첩 규칙 위반뿐입니다** (`AGENTS.md` §3-2). 새 실패 경로를 추가하지 않습니다.
- 위반 직전 경고를 노출하지 않습니다 (`AGENTS.md` §3-4).
- 실패 상태 감지와 전체 진행 저장을 한 책임에 섞지 않습니다.

### 시야 감지

- 대상이 플레이어 시야 내인지 판정합니다. 용도: 시야 밖 오브젝트 스왑, 응시 판정, 특정 시각의 목격 판정.
- **전시물이 변화하는 순간은 시야 밖에서만 처리합니다** (`AGENTS.md` §3-3).

## 상태 소유권 경계

### 현재 시나리오 재시작 시 초기화되는 상태

- 현재 시나리오 목표 진행도
- 현재 시나리오 전용 이상 현상 상태
- 현재 시나리오 전용 오브젝트 위치
- 현재 밤 전용 조명·전원 상태
- 현재 밤 중 수첩에 필사된 현장 수칙
- 현재 밤 중 획득한 임시 단서
- 현재 밤의 플레이어 배터리 잔량과 배터리 배치(밤마다 리셋)

### 현재 밤 실패 후에도 유지되는 상태

- 이전 밤 클리어 기록
- 이전 밤에서 해금된 기본 기능
- 획득한 RULE_FRAGMENT
- 공통 플레이어 조작 설정
- 전체 게임 진행도
- 재기동 횟수 로그 누적

현재 밤 초기화 상태와 전체 진행 유지 상태를 같은 임시 변수나 개별 시나리오 Actor에 혼합하지 않습니다. 밤 시작 시 경비실 스폰은 ScenarioManager 책임, 시각 복구는 GameClock 책임을 통해 조정하는 것을 우선합니다.

**밤-간 변화 상태**(밤2에서 보관한 아래턱뼈가 밤3에 화석으로 돌아와 있는 것 등)는 위 두 분류와 별개로, 시나리오 ID를 키로 하는 스폰 테이블에서 관리합니다 (GDD §8·§11-3).

## 시나리오 자산 경계

- 시나리오 전용 자산은 `S01`부터 `S03`까지의 ID로 소유 범위를 구분합니다. **출시 기준 밤은 3개이며, 밤 3개가 완성되기 전에는 ID를 늘리지 않습니다** (GDD §11-2).
- 여러 밤이 공유하는 기능은 특정 시나리오 폴더에 두지 않습니다.
- 특정 밤 종료 또는 재시작 시 초기화되어야 하는 특수 오브젝트는 초기화 진입점을 추적할 수 있게 구성합니다.
- S01~S03의 업무, 규칙, 이상 현상, 연출은 **GDD §6에 확정되어 있습니다.** 자산명·클래스명은 GDD 내용을 근거로 짓고, GDD에 없는 내용을 임의로 확정하지 않습니다.

## 권장 파일 배치

- 파일은 먼저 이 문서에 기록된 책임 경계를 기준으로 배치합니다.
- 같은 성격의 파일은 기존에 정의된 책임 폴더를 우선 재사용합니다.
- 현재 task에서 실제로 생성된 대표 파일과 한 줄 역할을 `Aeterna 초기 상태` 구역에 갱신합니다.

## 변경 원칙

- 파일이 기존 책임 폴더로 배치될 수 없으면 새 폴더가 필요한 이유와 범위를 사용자에게 알리고 승인받습니다.
- 새 폴더, 새 플러그인, 새 모듈, 대규모 리팩터링 같은 범위 밖 변경은 `Docs/WORKFLOW.md`의 `진행 제약`을 따릅니다.
- 새 폴더를 생성하면 이 문서에 해당 폴더와 역할을 추가합니다.
- 시스템 책임 또는 시나리오 상태 소유권을 변경하면 관련 테스트 기준과 `Docs/RULE_ORIGINS.md`도 함께 확인합니다.
