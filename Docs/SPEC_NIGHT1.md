## 1. 상태머신

밤1은 선형 튜토리얼이므로 시나리오 BP가 아래 상태를 순서대로 진행한다.
스캔 3곳(§3)은 `Patrol` 상태에서 **순서 무관** 병렬 목표다.

```
[Boot] → [PickupNotebook] → [ReadNotebook] → [HeadlampReady] → [Patrol] → [Complete]
```

| 상태 | 진입 조건 | 내용 | 이탈 조건 |
|---|---|---|---|
| `Boot` | 시나리오 시작 | 암전 + 부팅 로그 스크롤 `M-05 RESTORE... CAMERA ON` (총 4.0s `[제안]`) → 카메라 온. 입력 잠금(시점 포함) | 로그 종료 |
| `PickupNotebook` | Boot 종료 | 이동·시점 해금. 책상 위 수첩만 상호작용 가능(§3-0). **경비실 문 잠금** `[제안]` — 프롬프트 `[E] (잠김)` 대신 문에 상호작용 없음, 콜리전만 | 수첩 `E` 획득 |
| `ReadNotebook` | 수첩 획득 | 화면 좌하단 힌트 `Tab — 수첩` 표시(수첩 첫 열람 전까지 유지). 수첩 열람 시 p.1 기본 수칙 + 인수인계 문구 표시 | 수첩을 열었다 닫음 |
| `HeadlampReady` | ReadNotebook 종료 | 시스템 로그 1줄 `HEADLAMP: READY` + 힌트 `F — 헤드램프`. **경비실 문 해금**. 클럭 시작(§4) | 즉시 (게이트 아님 — 문 해금과 로그만 수행) |
| `Patrol` | HeadlampReady | 스캔 3곳 활성. 진행도는 `UAeternaScanProgressComponent`가 집계 | `BP_AllRequiredScansCompleted` 수신 |
| `Complete` | 3스캔 완료 | §5 종료 시퀀스 | — |

- `[확정]` 헤드램프는 `Boot` 직후부터 `F`로 사용 가능하다 (기능 잠금 없음). `HeadlampReady`는 안내 타이밍일 뿐 게이트가 아니다 — 어차피 경비실은 밝고, 잠금 로직을 늘리지 않는다 (기능 최소주의)
- `[제안]` 수첩 획득 전 문 잠금은 튜토리얼 이탈 방지용 최소 게이트 1개. 이것 외의 강제 순서 없음

## 4. 클럭 설정

| 항목 | 값 |
|---|---|
| ConfigureClock | Start `60` / End `300` / `GameMinutesPerRealSecond = 1.0` `[제안]` (구현 기본값 유지) |
| 근거 | 배속 1.0이면 240 게임분 = **실시간 240초(4분)**. 실플레이 15~20분 중 첫 4분 동안 시계가 눈에 띄게 돌아 "밤이 흐른다"를 보여주고, 이후 04:59에서 멈춘다. 밤1의 클럭은 판정에 안 쓰이는 배경 소품이므로(시각 이벤트 없음, 종료는 스캔 기반) 이 정도면 충분하고, 밤1 전용 배속값을 만들지 않는다. 플레이 시간에 맞춰 느리게(≈0.25) 갈지는 §10 #2 페이싱 튜닝에서 밤2·3과 함께 결정 |
| 시각 이벤트 | **없음** `[확정]` — 밤1은 `SetClockEvents` 빈 배열. 44분·03:03 등 이벤트 학습은 밤2부터 |
| 시작 시점 | 상태머신 `HeadlampReady` 진입 시 `StartClock` — 경비실 튜토리얼 중에는 시간 정지 (수첩을 천천히 읽어도 손해 없음) |

**05:00 도달 처리 (GDD §10 #15 — 본 스펙에서 확정)**

- `[제안]` **05:00 도달은 무처리** — `OnClockFinished`를 밤1에서는 구독하지 않는다. 시계는 04:59에서 멈춘 것처럼 보이게 두고(`OnClockFinished` 후 진행 정지는 구현 기본 동작), 3스캔 완료만이 종료 조건
- 근거: 밤1은 "실패 없음"이 확정이고, 배속 2.0에서 05:00은 시작 2분 뒤에 온다 — 타임아웃으로 쓸 수 없는 시계다. 05:00을 의미 있게 만들려면 배속을 실플레이에 맞춰야 하는데, 그 페이싱 튜닝(§10 #2)을 밤1 스코프로 끌고 오지 않는다
- 수첩 "05:00 전에는 밖으로 나가지 마시오" 위반(= 박물관 출입구 접근): `[제안]` 밤1에는 열리는 외부 출입구를 **배치하지 않는다**. 규칙 위반 상황 자체를 만들 수 없게 하는 것이 부정 피드백 설계보다 싸다. 외부 문이 보이면 상호작용 없는 프롭으로만

## 5. 종료 시퀀스 (`Complete` 상태)

```
BP_AllRequiredScansCompleted 수신
 → [0.0s] 입력 잠금 (이동·시점 유지 여부: 시점만 허용 [제안])
 → [0.0s] 시스템 로그: `순찰 완료 3/3 — 근무 기록 저장`
 → [0.5s] 수첩 체크선 SFX (수첩 UI 강제 오픈은 하지 않음 [확정])
 → [2.0s] 페이드아웃 시작 (1.5s 블랙까지)
 → [3.5s] 「Day 1」 카드 표시 + `RULE_FRAGMENT_03` 획득 표시 (텍스트: §10 #5 대기)
 → [카드 입력 대기 or 4.0s 자동 [팀 결정]]
 → ScenarioManager.CompleteCurrentScenario() → 밤2 로드
```

- `[확정]` 마지막 스캔이 어느 지점이든 **그 자리에서** 시퀀스 시작 (경비실 복귀 없음)
- 배선: `UAeternaScanProgressComponent` 완료 → Character `BP_AllRequiredScansCompleted` → 시나리오 BP가 수신 → 위 시퀀스 실행 → `CompleteCurrentScenario`. **이것이 ScenarioManager 첫 실사용 경로다** (IMPLEMENTED.md §7의 배선 작업과 동일 마일스톤)

## 13. 구현 반영 (2026-08-27)

> 본 절은 스펙과 실제 코드가 다른 지점만 기록한다. 언급 없는 항목은 스펙대로다.

### 13-1. 배터리가 둘로 나뉘었다

스펙 §3-2는 배터리 하나가 "충전 + 스캔 등록"을 겸한다. 그대로 밤2·밤3에
배터리를 놓으면 **밤2가 깨진다** — 뼈 12개를 세는 집합과 스캔 진행도가 같아서,
배터리 하나가 뼈 하나로 세어져 11개만 맞춰도 밤이 끝난다.

그래서 역할을 나눴다.

| 액터 | 역할 | 진행도 | 활성 밤 |
|---|---|---|---|
| `BP_S01_ScanPoint_Battery` (`AS01ScanPointActor`) | 밤1 목표 3곳 중 하나 | 1 더함 | 밤1 |
| `BP_BatteryPickup` (`AAeternaBatteryPickupActor`) | 순수 충전 자원 | 관여 안 함 | 전부 |

- `[정리 예정]` `AS01ScanPointActor`의 `ApplyScanPointDefaults()`가 매 `OnConstruction`마다
  값을 덮어써서 인스턴스별 설정이 불가능한 것이 별도 클래스를 만든 이유다.
  종류를 하나 추가해 클래스를 합칠 수 있다 — 이때 `S01` 접두도 함께 정리한다

### 13-2. 상호작용이 밤 시작마다 풀린다

`bInteractionCompleted`가 한 번 서면 되돌아오지 않아, **게임 오버 후 재시작하면
스캔을 다시 할 수 없어 밤을 클리어할 방법이 없었다.** 진행도는 초기화되는데
액터가 잠긴 채 남았기 때문이다.

`AAeternaInteractableActor`가 `OnScenarioStarted`를 구독해 되돌린다. BP가 숨긴
메시는 BP가 되살려야 하므로 `Interaction Reset` 이벤트를 함께 둔다.

### 13-3. 조준 보정

`InteractionBounds`보다 가까이 가면 카메라가 박스 안에 들어가 라인트레이스가
대상을 놓친다. 트레이스가 실패했을 때만 카메라 주변을 구체로 한 번 더 훑는다
(`InsideBoundsProbeRadius`, 기본 25cm).
