## 후속 확장 원칙

- S02, S03은 GDD §6에 기획이 확정되어 있으므로, S01 수직 조각 검증이 끝난 뒤 하나씩 작업리스트에 추가합니다.
- 각 밤은 기획 반영, 겉 업무, 규칙·이상 현상, 클리어·실패 통합을 필요에 따라 작은 task로 나눕니다.
- S01에서 실제로 검증되지 않은 데이터 구조나 공통 시스템을 S02~S03용으로 선제 확정하지 않습니다.
- GDD §11의 확장 시나리오는 **밤 3개 완성 전에는 작업리스트에 넣지 않습니다** (스코프 방어).
- GDD §10 `결정 대기` 항목에 걸리는 단계는 결정이 끝나기 전에 구현을 시작하지 않습니다.
- 이전 task의 사용자 결과 확인이 끝나기 전에는 다음 단계로 넘어가지 않습니다.

## 상태 범례

- `예정`: 아직 task 문서가 없거나 구현 시작 전
- `진행중`: 구현 중이거나, 구현 후 사용자 수동 작업 또는 결과 확인을 기다리는 상태
- `완료`: 구현과 현재 확인 모드 기준 결과 확인이 완료된 상태
