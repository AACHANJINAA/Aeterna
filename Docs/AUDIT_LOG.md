# Audit Log

## 목적

이 문서는 하네스 감사, 즉 문서 간 중복·충돌·정합성 점검의 체크리스트와 이력을 보관합니다.

- 평소 작업에서는 읽지 않습니다. 사용자가 감사를 요청할 때만 참조합니다.
- 감사는 정기·자동 절차로 강제하지 않고, 사용자가 필요할 때 요청하여 진행합니다.
- 감사에서 나온 규칙 변경은 `docs/HARNESS.md`의 절차와 `docs/RULE_ORIGINS.md` 기록을 따릅니다.

## 감사 체크리스트

### 규칙 품질

- 같은 의미의 규칙이 여러 문서에 중복되어 있는가
- 규칙끼리 모순되는가
- 규칙이 담당 문서에 있는가
- 반복 실패한 훈계형 규칙이 양식·체크리스트 같은 작동 지점으로 승격되어 있는가
- 실패 사례나 설계 이유가 없는 규칙이 불필요하게 쌓이지 않았는가

### 구조 정합성

- 절차와 양식이 일치하는가
- `AGENTS.md` 문서 맵이 실제 파일 목록과 일치하는가
- `docs/`에 정확히 11개 운영 문서가 있는가
- `Tasks/template.md`와 `Tasks/MAKE_REQUEST.md` 경로 참조가 일치하는가
- 작업 흐름 단계 번호 참조가 깨지지 않았는가
- 현재 폴더 책임 기록이 실제 Source·Content 구조와 일치하는가

### Aeterna 기획 정합성

- S01~S08과 01:00~05:00의 30분 슬롯 매핑이 유지되는가
- 모든 시나리오가 경비실 시작·종료 원칙을 따르는가
- 실패가 현재 시나리오만 재시작하는가
- 초기화 상태와 유지 상태의 경계가 문서와 구현에서 일치하는가
- 수첩 중심 규칙 전달이 다른 UI 자동 해답으로 대체되지 않았는가
- 승인되지 않은 시나리오 제목, 업무, 규칙, 이상 현상, 연출을 문서나 코드가 임의 확정하지 않았는가

### 기록 정합성

- `docs/RULE_ORIGINS.md`가 본문 규칙과 일치하는가
- 장부에 행동 규칙이 숨어 있지 않은가
- 완료 상태와 task 문서 체크박스가 일치하는가
- 이전 프로젝트 기록이 `PLANS`, `LOGS`, `PENDING_ISSUES`에 이월되지 않았는가

### 검증 방법

- 실제 task 문서, 최근 로그, 보류 의심과 대조했는가
- 규모가 크거나 판단이 갈리는 감사라면 교차 리뷰가 필요한지 판단했는가
- 자동화 제안이 실제 반복 실패보다 앞서 과도하게 도입되지 않았는가
