# Audit Log

## 목적

이 문서는 하네스 감사, 즉 문서 간 중복·충돌·정합성 점검의 체크리스트와 이력을 보관합니다.

- 평소 작업에서는 읽지 않습니다. 사용자가 감사를 요청할 때만 참조합니다.
- 감사는 정기·자동 절차로 강제하지 않고, 사용자가 필요할 때 요청하여 진행합니다.
- 감사에서 나온 규칙 변경은 `Docs/HARNESS.md`의 절차와 `Docs/RULE_ORIGINS.md` 기록을 따릅니다.

## 감사 체크리스트

### 규칙 품질

- 같은 의미의 규칙이 여러 문서에 중복되어 있는가
- 규칙끼리 모순되는가
- 규칙이 담당 문서에 있는가
- 반복 실패한 훈계형 규칙이 양식·체크리스트 같은 작동 지점으로 승격되어 있는가
- 실패 사례나 설계 이유가 없는 규칙이 불필요하게 쌓이지 않았는가

### 구조 정합성

- 절차와 양식이 일치하는가
- `AGENTS.md` 문서 맵이 실제 파일 목록과 일치하는가
- `Docs/`에 기획 원본(GDD) 1개 + 운영 문서 11개가 있는가
- `AGENTS.md` §9 문서 지도가 실제 `Docs/`·`Tasks/` 파일 목록과 일치하는가
- `Tasks/template.md`와 `Tasks/MAKE_REQUEST.md` 경로 참조가 일치하는가
- 문서 간 상호 참조가 실재하는 파일과 섹션을 가리키는가 (존재하지 않는 문서·섹션 번호 참조 금지)
- 경로 참조의 대소문자가 실제 폴더명(`Docs/`, `Tasks/`)과 일치하는가
- 작업 흐름 단계 번호 참조가 깨지지 않았는가
- 현재 폴더 책임 기록이 실제 Source·Content 구조와 일치하는가

### Aeterna 기획 정합성

> 판단 기준은 `Docs/GDD_v1.3_에테르나.md`입니다. 어떤 문서든 GDD와 다르면 **문서 쪽이 틀린 것**으로 봅니다.

- 시나리오 ID가 `S01`~`S03` 범위를 벗어나지 않는가 (밤 3개)
- 밤 1개를 시간 슬롯으로 쪼개는 서술이 남아 있지 않은가 (각 밤 = 01:00~05:00 전체)
- 밤 시작만 경비실이고, **클리어 후 경비실 복귀 로직이 어디에도 없는가** (GDD v1.3에서 폐기)
- 클리어 흐름이 완료 지점 페이드아웃 →「Day N」카드로 서술되어 있는가
- 게임 오버 경로가 **수첩 규칙 위반 하나뿐인가** (배터리·타임아웃 등 새 실패 경로 없음)
- 위반 직전 경고 UI가 문서나 구현에 들어와 있지 않은가
- 조작이 WASD·Shift·Tab·E·F 5입력을 벗어나지 않는가
- 전시물의 변화가 플레이어 시야 밖에서만 일어나는가
- 규칙·시각 이벤트·실패 조건이 DataTable(CSV)을 경유하고 하드코딩되지 않았는가
- 게임 오버가 현재 밤만 재시작하고, 초기화 상태와 유지 상태의 경계가 문서와 구현에서 일치하는가
- 수첩 중심 규칙 전달이 다른 UI 자동 해답으로 대체되지 않았는가
- GDD §6에 없는 시나리오 제목, 업무, 규칙, 이상 현상, 연출을 문서나 코드가 임의 확정하지 않았는가
- GDD §10 `결정 대기` 항목을 구현이 먼저 확정해버리지 않았는가
- 담당 구분이 GDD §9의 고정 담당제(A~D)와 서브레벨 1담당제를 따르는가

### 기록 정합성

- `Docs/RULE_ORIGINS.md`가 본문 규칙과 일치하는가
- 장부에 행동 규칙이 숨어 있지 않은가
- 완료 상태와 task 문서 체크박스가 일치하는가
- 이전 프로젝트 기록이 `PLANS`, `LOGS`, `PENDING_ISSUES`에 이월되지 않았는가

### 검증 방법

- 실제 task 문서, 최근 로그, 보류 의심과 대조했는가
- 규모가 크거나 판단이 갈리는 감사라면 교차 리뷰가 필요한지 판단했는가
- 자동화 제안이 실제 반복 실패보다 앞서 과도하게 도입되지 않았는가
