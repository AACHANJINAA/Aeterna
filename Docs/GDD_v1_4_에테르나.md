# 1. 게임 개요

## 1-1. 하이 콘셉트

> **"낡은 박물관의 야간 관리 로봇 M-05가 되어, 전임자가 남긴 수첩의 규칙을 지키며 밤의 점검 업무를 완수하라. 수첩과 다른 행동을 하는 순간 — 게임 오버, 그 밤은 처음부터 다시 시작된다."**

## 1-2. 코어 루프 (확정)

```
[경비실] 재기동 (밤 시작)
   ↓
수첩 확인 (오늘 밤의 업무 + 규칙)
   ↓
해당 장소로 이동
   ↓
퀘스트 진행  ──  수첩과 상이한 행동 → [게임 오버] → 밤 처음부터 재기동
   ↓
퀘스트 완료 → 페이드아웃 → 「Day N」 카드 표시
   ↓
다음 밤, [경비실] 재기동
```

- 밤1(튜토리얼) → **Day 1** → 밤2 → **Day 2** → 밤3 → **Day 3** → 엔딩
- **경비실 복귀 없음**: 마지막 목표를 완료한 그 자리에서 화면이 페이드아웃되고, 검은 화면에 「Day N」 타이틀 카드(+ RULE_FRAGMENT 획득 표시)가 뜬 뒤 다음 밤의 경비실 재기동으로 이어진다. 밤의 시작만 경비실 고정
  - 예외: 밤3의 "빨간 불" 규칙은 **밤 도중** 경비실로 도망치는 행동을 요구한다 — 이는 밤 종료가 아니라 규칙 수행이다 (§6 NIGHT 3)
- 밤은 확장 가능한 단위: 추후 시나리오가 추가되면 밤3과 엔딩 사이(또는 엔딩 이후 추가 근무)로 삽입한다 (§11)
- **게임 오버 = 실패 연출 후 현재 밤을 처음부터 재시작** (이전 밤 클리어 기록·해금 요소는 유지)

## 1-3. 디자인 기둥

1. **업무는 평범하게, 규칙은 기이하게** — 공포는 수첩 규칙과 실제 상황의 충돌에서만 발생
2. **보여주지 않는 공포** — 전시물이 움직이는 순간은 절대 보여주지 않는다 (시야 밖 변경만)
3. **판단은 플레이어 몫** — 위반 직전 경고 없음. 규칙을 기억하고 해석하는 것이 게임플레이
4. **기능 최소주의** — 조작 5종 이외의 기능은 만들지 않는다 (4인 팀 스코프 방어)

## 3-2. 헤드램프 & 플레이어 배터리 시스템

조명은 별도 아이템이 아니라 **M-05 머리 위에 내장된 헤드램프**다 (`F` ON/OFF).
배터리는 **플레이어(M-05) 배터리** 하나로 통합된다 — **M-05 본체 전원과 헤드램프 전원을 겸하는 단일 배터리**이며, 헤드램프가 이 배터리를 소모한다.

| 항목 | 사양 |
|---|---|
| 헤드램프 | M-05 내장 — 획득 과정 없음, 밤1 시작부터 사용 가능. 빛 방향 = 시선 방향 |
| 소모 | 헤드램프 ON 동안 플레이어 배터리 감소 (OFF 시 소모 없음) |
| **밝기 연동** | **잔량이 줄어들수록 헤드램프가 연속적으로 어두워진다** — 아래 「잔량-밝기 연동」 참조 |
| 방전 시 | 헤드램프 사용 불가 — 어둠 속 이동 강제 (게임 오버 아님, 단 규칙 수행이 어려워짐) ※ "방전 = M-05 기능 정지" 여부는 결정 대기 (§10 #8). 방전 시 헤드램프 자동 OFF는 구현됨 |
| 충전 | 맵에 배치된 배터리 에셋에 `E` → 즉시 충전 (구현 기본값: 1회 +35) |
| 배치 | 경비실 + 각 구역 파밍 포인트 (밤1은 진열장 맞은편 배터리로 충전을 학습시킨다 — §6) |

### 잔량-밝기 연동 (확정 · 구현 완료)

배터리는 본체와 헤드램프를 함께 먹이므로, **전압이 떨어지면 빛도 약해진다**는 물리적 인과를 그대로 게임에 쓴다.
잔량이 줄어들면 아래 파라미터를 **함께, 연속값으로** 감쇠시킨다. 구현은 완료되었고 아래 값은 **초기 튜닝값**이다 (`UAeternaBatteryComponent`, 최종 밸런스는 §10 #3).

| 파라미터 | 만충 → 방전 직전 (초기 튜닝값) | 역할 |
|---|---|---|
| 강도 (Intensity) | `8000` → `600` | 전체 광량 |
| **도달 거리 (Attenuation Radius)** | `1600cm` → `350cm` | **체감의 핵심** — 빛이 닿는 거리가 줄어야 "좁아진다"가 느껴진다 |
| 색온도 | `6500K` → `2600K` (백색 → 주황) | 전압 강하의 다이어제틱 표현 |
| 콘 각도 (Inner/Outer) | `18°/36°` → `10°/22°` | 시야 폭 축소 |

- 감쇠 곡선 지수 `1.8` (후반 가중) / 최대 잔량 `100`, 소모 `2.5/s` — 초기 튜닝값
- **연속값으로 감쇠한다.** UI 게이지는 칸 단위로 표시하지만 밝기는 칸 경계에서 뚝 떨어지지 않는다 — 칸이 깎일 때만 어두워지면 플레이어가 "칸이 남아 있으면 안전"으로 학습해 긴장이 끊긴다.
- 감쇠는 선형이 아니라 **후반 가중**: 초반에는 거의 눈치채지 못하다가 후반에 급격히 조여드는 곡선 (지수값 튜닝은 §10 #3)
- 마지막 1칸의 **점멸**은 이 연속 감쇠 위에 얹히는 별개 신호다 (아래 UI 항목).
- 방전(0) 시에는 감쇠의 연장이 아니라 **소등**된다 — 헤드램프 사용 불가.

**설계 의도**

- **밝기 자체가 다이어제틱 배터리 게이지가 된다.** 플레이어는 구석의 UI 위젯을 보지 않아도 "요즘 잘 안 보이네"로 잔량을 체감한다 — §7의 "정보의 출처" 원칙과 어긋나지 않으면서 HUD 의존을 줄인다.
- 자원 관리의 압박이 숫자가 아니라 **시야 폭**으로 전달된다. "언제 켜고 언제 끌 것인가"의 대가가 즉각 보인다.
- 어두워질수록 다음 배터리를 찾기 어려워지는 **하강 나선**이 생긴다. 긴장 장치인 동시에 소프트락 위험이므로 완화 장치가 필요하다 (§10 #10).

**플레이어 배터리 UI (상시 표시 · 구현 완료)**

```
🔋 ▮▮▮▯▯      ← 배터리 잔량 칸 게이지
```

- 잔량은 숫자가 아닌 **칸 단위 게이지**로 표시 — 좌하단 소형 위젯 (구현: 10칸 세그먼트 + 퍼센트, 잔량에 따라 노랑→빨강)
- 마지막 1칸 진입 시 게이지 점멸 + 헤드램프 **점멸** 추가 — 연속 감쇠 위에 얹히는 **별개의 경고 신호** (점멸은 미구현, 스펙 문서에서 정의)
- "언제 켜고 언제 끌 것인가"가 자원 관리의 핵심
- 헤드램프 빛이 시선과 일치하므로, **"비추지 마라" 계열 규칙(밤2 눈구멍)은 곧 "보지 마라"와 동일 판정**이 됨 — 응시 판정 하나로 통합 가능 (구현 단순화, 헤드램프 OFF 시의 판정은 §10 #13)

| 채널 | 역할 |
|---|---|

- **"수첩에 적힌 내용과 상이한 행동 = 게임 오버"** 가 유일한 실패 규칙 (배터리 방전은 게임 오버가 아니라 플레이를 어렵게 만드는 리스크 — §10 #8 결정 대기)

## NIGHT 3 — 「켜져 있으면 안 되는 불」

| 항목 | 내용 |
|---|---|
| 게임 내 시간 | 01:00 ~ 05:00 (핵심 시각: **03:03** 확인등) |
| 무대 | **2층 전시관** — 경비실 → 2층 복도·전시 구역 → 배전실. **1층은 Box Collider로 진입 차단** (경비실·배전실 동선 제외) |
| 수첩 「오늘의 업무」 | *"2층 전시관 점검"* |
| 겉 업무 | 01시 이후 켜진 비정상 조명 소등 |
| 핵심 반전 | "켜진 불은 끄시오" vs "03:03의 불은 건드리지 마시오" — **규칙 1과 2의 충돌을 스스로 판별**해야 한다 |
| 밤-간 연속성 | 도입 연출은 `SPEC_NIGHT3.md`에서 확정 (v1.3의 아래턱뼈 비트는 밤2 개정으로 폐기) |

### 규칙 (확정 — 3개. 수첩 기재, 스캔 시 필사)

```
1. 1시 이후 켜진 불은 끄십시오. 박물관에 다른 근무자는 없습니다.
2. 03:03에 켜지는 불은 근무자를 확인하는 불입니다. 건드리지 마십시오.
3. 빨간색 불이 켜지는 걸 목격하셨다면 경비실로 도망치십시오.
```

**규칙별 게임플레이 역할**

| 규칙 | 유형 | 판정 |
|---|---|---|
| 1 | 업무 목표 + 불길한 암시 ("다른 근무자는 없다"인데 불은 계속 켜진다 — 그럼 누가?) | 켜진 불을 찾아가 `E`로 소등. 확인등 제외 전부 소등이 종료 조건 |
| 2 | 규칙 1과의 충돌 — **예외를 식별하는 판단력 시험** | 03:03에 켜진 그 불을 조작(소등)하면 게임 오버. 시각(03:03)이 유일한 식별 근거 → **시계 UI 확인이 생존 행동** |
| 3 | 긴급 이탈 이벤트 | 빨간 불 점등 목격 시 제한 시간 내 경비실 도달 필요 — 발동 조건·제한 시간·실패 판정은 §10 #17, `SPEC_NIGHT3.md` |

> 이 밤의 공포 문법: 규칙 1을 성실히 수행할수록 "그럼 이 불들은 누가 켜는가"라는 질문이 쌓이고,
> 03:03에 켜진 불 하나만은 **끄면 안 되는 예외**임을 플레이어가 스스로 구분해야 한다.
> 규칙 3은 소등 루틴을 강제로 끊고 전 구역을 가로지르게 만드는 긴급 이벤트다.

### 흐름 골격

1. **재기동·규칙 획득 (01:00)** — 수첩 「오늘의 업무」 확인 → 규칙 3개 획득 (획득 위치는 스펙 문서)
2. **소등 순찰** — 2층 조명이 시간차로 하나씩 점등, 시스템 로그가 통지: `비정상 점등 감지: 2층 복도` → 찾아가 `E` 소등. 끈 불이 등 뒤에서 다시 켜지는 연출 1회 ("다른 근무자는 없습니다"의 회수)
3. **03:03 — 확인등 (판단력 시험)** — 여느 점등 통지와 **똑같은 형식**의 로그로 점등. 스캔만 하면 로그 `광원 분석 불가` (방치가 정답). 끄면 안내 방송 `근무자 미확인` → 게임 오버
4. **빨간 불 이벤트** — 발동 시 경비실로 도망 (규칙 3). 횟수·타이밍은 스펙 문서
5. **점검 종료** — 확인등 제외 전 소등 → 배전반에서 점검 종료 → 페이드아웃 → 엔딩 시퀀스

### 클리어 / 실패

- **클리어**: 03:03 확인등을 제외한 비정상 조명 전부 소등 + 빨간 불 이벤트 대응 성공 + 05:00 전 배전반 점검 종료
- **게임 오버 (= 규칙 위반)**: ① 03:03 확인등 조작 ② 빨간 불 목격 후 경비실 도달 실패 / 실패(재시작): 비정상 조명 방치 상태로 05:00 도달 (판정 단일화는 §10 #12)
- **실패 연출**: 전소등 → 야간 모드에도 아무것도 안 보임 → 조명이 하나씩 재점등, 각 불빛 아래 M-05형 그림자가 서 있음
- **클리어 연출**: 페이드아웃 직전, 어두워진 박물관에 03:03의 불 하나만 남아 있음 — 그 불이 천천히 꺼진다. *근무자 확인 완료.*
- **최종 밤**: 「Day 3」 카드 + `RULE_FRAGMENT_02` 획득 표시 → RULE_FRAGMENT 3개 회수 엔딩 시퀀스 (아침 햇살이 드는 중앙홀 등, 연출 별도 기획)

# 7. UI / UX — 에셋 활용 방침

UI는 마켓플레이스 UI 에셋(위젯 팩)을 사용하고, 게임 고유 요소만 커스텀한다.

| UI 요소 | 방식 | 조달 / 상태 |
|---|---|---|
| 화면 시계 | 상시 소형 시계 위젯 (별도 조작 없음) | **구현 완료** (C++ Slate, `HH:MM` 디지털 패널) |
| 플레이어 배터리 UI | 잔량 칸 게이지, 마지막 칸 점멸. **잔량은 헤드램프 밝기로도 상시 전달되므로**(§3-2) 보조 지표 — 작고 눈에 덜 띄게 | **구현 완료** (10칸 세그먼트, 좌하단. 점멸은 미구현) |
| 상호작용 프롬프트 | 조준 시 `[E] <문구>` 컨텍스트 표시 (라벨 가변), 성공 시 피드백 | **구현 완료** (문구 String Table 이관 필요, §9) |
| 수첩 | Tab 수첩 뷰 + **「오늘의 업무」 두루마리형 위젯**(`[확인]` 닫기) | 프로토타입 → UI 확정 §10 #16. 페이지 넘김 입력은 §10 #9 |
| 시스템 로그 | 화면 상단 타자기식 텍스트 (부팅/스캔/연출용) | 에셋 타이핑 위젯 or 간단 자체 제작 |
| 부팅/게임 오버 시퀀스 | 풀스크린 로그 스크롤 | 자체 제작 (단순) |
| 「Day N」 카드 | 밤 완료 시 페이드아웃 후 풀스크린 타이틀 + RULE_FRAGMENT 획득 표시 | 자체 제작 (단순) — 미착수 |
| 자막 | 로그·연출음 표기 (접근성) | 에셋 |

- 다이어제틱 원칙은 "정보의 출처"에 유지(규칙은 수첩에서만), 표시 자체는 에셋 위젯으로 실용화
- 로봇 시점이므로 화면 UI가 "M-05의 HUD"라는 세계관적 정당성이 있음 — 시계·게이지 상시 표시가 설정과 충돌하지 않음

# 9. 기술 · 협업

- **UE 5.6** / Git + LFS + 파일 잠금 / 서브레벨 1담당제 (상세: `AGENTS.md` §2·§5, 작업 절차는 `Docs/WORKFLOW.md`)
  - ⚠️ LFS 미설정·경로 규약 미준수 등 현황과 규약의 차이는 `IMPLEMENTED.md` §6 참조 — 정리 필요
- 코어는 C++ (GameClock, ScenarioManager, FailureSystem, NotebookRules, 시야 감지), 연출은 BP
  - 구현 원칙(적용 중): **C++가 판정하고 BP는 연출만** — 상호작용·배터리·스캔이 이미 이 구조로 구현됨
- 규칙·시각 이벤트·조명 ID·실패 조건은 DataTable(CSV)로 — 기획 수정이 바이너리를 건드리지 않게. **밤별 스펙 문서가 이 DataTable 스키마의 원본이 된다**
- 프롬프트·수첩 등 노출 텍스트는 String Table로 (현재 C++ 하드코딩 → 이관 필요)
- **시나리오 = 데이터 + 전용 BP 1세트** 원칙: ScenarioManager는 시나리오 목록을 DataTable에서 읽으므로, 새 시나리오 추가 시 코어 C++ 수정 없이 행 추가 + 시나리오 BP/에셋만 제작하면 된다 (§11 확장 대비)
- 다음 배선 우선순위: **ScenarioManager → GameClock 연결** (`StartScenario` → `ConfigureClock`+`StartClock`, `OnClockFinished` → 완료 처리). 선행 조건: 시나리오 DataTable 스키마 확정 = 스펙 문서 작성

| 담당 | 범위 | 현황 요약 |
|---|---|---|
| A. 시스템 | GameClock, ScenarioManager, FailureSystem, 세이브 | 뼈대만 (배선·Failure·세이브 미착수) |
| B. 플레이어 | M-05 조작(5입력), 헤드램프·배터리, 스캔, 수첩·UI 에셋 통합 | 거의 완성 (수첩 내용 표시만 남음) |
| C. 레벨 | 서브레벨, 라이팅(점등 스케줄 포함), 경비실·배전실 프롭 | 아트 패스 진행 중 |
| D. 시나리오 | 밤1~3 스크립팅(스펙 문서 작성 포함), 사운드, 실패/클리어 연출 | 미착수 — **스펙 문서 3종이 첫 산출물** |

# 11. 시나리오 확장 계획 (출시 이후 / 여유 발생 시)

밤 3개는 출시 기준 최소 구성이며, 시나리오는 추후 계속 추가할 수 있는 구조로 설계한다.

## 11-1. 확장 원칙

- 새 시나리오도 동일한 프레임을 따른다: **경비실 시작 / 하룻밤(01:00~05:00) / 수첩 규칙 / 위반 = 게임 오버 / 완료 지점 페이드아웃 → 「Day N」 카드 + RULE_FRAGMENT**
- 조작 5입력 체계는 확장 시나리오에서도 불변 (기능 최소주의 유지)
- 신규 전시물 에셋 1~2종 + 규칙 세트만 있으면 시나리오 1개가 성립하도록 — 전시관 하나 = 괴담 하나
- 신규 시나리오도 **스펙 문서 1편 = 시나리오 1개** 형식을 따른다 (`SPEC_NIGHT<N>.md`)

## 11-2. 후보 아이디어 (미확정 — 브레인스토밍 단계)

| 후보 | 소재 | 규칙 훅 (예시) |
|---|---|---|
| 중세 기사 갑옷 | 무기·갑주 전시관 | "갑옷의 개수를 세지 마시오." / "투구의 면갑이 열려 있으면 닫아 주시오. 안을 보지 말고." |
| (추가 후보 슬롯) | 이집트관, 해양관, 초상화 전시실 등 | 팀 브레인스토밍으로 채움 |

- 후보는 아이디어 풀일 뿐 스코프에 포함하지 않는다. **밤 3개 완성 전에는 착수 금지** (스코프 방어)

## 11-3. 시스템 확장 대비 (지금 해두면 되는 것)

- ScenarioManager의 시나리오 목록을 하드코딩하지 않고 DataTable 기반으로 (완료 시 자동으로 다음 행 로드)
- RULE_FRAGMENT 넘버링과 엔딩 조건을 "전체 개수 대비"로 판정 (3개 고정 아님)
- 서브레벨 네이밍 규칙에 확장 관 이름 여지 (`Sub_ArmoryHall` 등)
- 밤-간 변화 스폰 테이블을 시나리오 ID 키로 일반화
