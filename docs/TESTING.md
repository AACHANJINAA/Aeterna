# Testing

## 목적

이 문서는 AI 에이전트가 코드 구현 후 검증하는 기준과 절차를 정의합니다.

## 검증 원칙

<!-- 동기화 주의: 이 원칙은 Tasks/template.md의 `에이전트 확인` 체크박스, WORKFLOW.md 작업 흐름 9·10·14와 같은 검증 요구를 각각 다른 형태로 표현한다. 항목을 바꾸면 세 곳을 함께 확인한다. -->

각 task 구현 후 아래 순서로 검증합니다.

1. 관련 코드와 자산 수정 완료 여부 확인
2. 현재 실행 확인 모드에 맞는 정적 점검 또는 로컬 실행 확인
3. `docs/STYLEGUIDE.md` 기준으로 Unreal C++/Blueprint/에셋 규칙 위반 여부 확인
4. 현재 task의 구현 범위와 완료 조건 일치 여부 확인
5. 적용 범위에 해당하는 Aeterna 기획 기준과 상태 소유권 경계 확인
6. task 문서와 진행 현황 문서 갱신

## Aeterna 기획 기준 확인

현재 task가 시나리오 흐름, 시간, 경비실 복귀, 수첩, 실패 처리, 진행 저장 중 하나를 다룰 때만 아래 항목을 현재 구현 범위에서 확인합니다.

- 해당 슬롯과 시나리오 ID 연결이 `AGENTS.md`의 기획 기준과 맞는지
- 시작·클리어·실패 흐름에서 경비실 위치 책임이 일관적인지
- 실패 시 현재 시나리오 전용 상태만 초기화되는지
- 이전 시나리오 클리어 기록, 해금 기능, 공통 조작 설정, 전체 진행도가 의도치 않게 초기화되지 않는지
- 현재 시나리오 시작 시각과 수첩 규칙·업무 목표가 재시작 상태에 맞게 복구되는지
- 시나리오 전용 오브젝트·조명·경고·임시 단서 상태가 다음 실행이나 다른 시나리오로 누출되지 않는지

아직 구현하지 않은 시나리오 내용이나 다음 단계 기능을 현재 task의 확인 기준에 섞지 않습니다.

## 실행 확인 모드

현재 저장소의 기본 실행 확인 모드는 `수동 실행 확인`입니다. AI가 직접 에디터 실행과 인게임 확인까지 수행하면 비용이 크므로 기본은 사람이 실행과 결과 확인을 담당합니다.

- `수동 실행 확인`: 에이전트는 코드와 설정을 준비하고, 사람은 실제 실행과 결과 확인을 담당합니다.
- `에이전트 확인`: 사용자가 요청하거나 저장소 흐름상 필요할 때 에이전트가 로컬 실행 명령으로 에디터, 빌드, 또는 실행 동작을 확인합니다.

## 수동 실행 확인 모드

- 에이전트는 코드 눈검토, 관련 파일 점검, 기본 정적 확인을 수행합니다. 컴파일·빌드는 기본 정적 확인에 포함하지 않습니다.
- 사람은 코드 컴파일, Unreal Editor 실행, 맵 실행, PIE 또는 Standalone 실행, 입력 테스트, 기능 동작 확인을 수행합니다.
- 에이전트가 스스로 수행한 빌드·실행 결과는 사용자 확인을 대신하는 근거로 삼지 않으며, task 문서와 `docs/PLANS.md`에 사용자 확인 완료로 기록하지 않습니다.
- 수동 확인 항목은 현재 구현된 범위만 대상으로 삼습니다.
- 실패 시 어떤 맵, 시나리오 ID, 시간 슬롯, 입력, 상태 변화, UI, 조명, 오브젝트 반응이 문제인지 기록할 수 있어야 합니다.

## 에이전트 확인 모드

- 사용자가 요청하거나 현재 저장소 흐름상 필요할 때만 로컬 실행 확인을 수행합니다.
- 실행 명령은 현재 저장소의 기존 Unreal 실행 방식과 빌드 구조를 우선 사용합니다.
- 실행 결과를 기록할 때 사용자가 확인한 결과와 에이전트가 확인한 결과를 구분합니다.
