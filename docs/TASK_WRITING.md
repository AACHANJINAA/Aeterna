# Task Writing

## 목적

이 문서는 task 문서를 작성하거나 구현 후 갱신할 때 따라야 하는 규칙입니다.

## 기본 원칙

- task 문서는 현재 단계에서 필요한 결과와 검증 기준을 고정하는 문서입니다.
- task 문서에는 기본적으로 What, 즉 무엇이 필요한지를 적습니다.
- 구현 전 task 문서에는 How, 즉 내부 구현 방식, 파일 분리 방식, 함수 구조를 추측해서 적지 않습니다.
  - 단, 사용자의 요청에 How가 포함된 경우에는 해당 내용을 요청 범위로 반영합니다.
- 사용자 요청과 현재 task 범위를 벗어나는 항목은 추가하지 않습니다.
- 새 task 문서는 `Tasks/template.md`를 복사해 작성합니다.
- 새 task 문서를 생성하면 `docs/PLANS.md` 작업리스트의 해당 단계 `Task 문서` 칸을 실제 링크로 갱신합니다.

## Aeterna task 범위 원칙

- 하나의 task는 사람이 확인할 수 있는 하나의 핵심 결과를 중심으로 작성합니다.
- 공통 시스템, 특정 시나리오 콘텐츠, 에디터 자산 대량 구성, 전체 8개 시나리오 구현을 한 task에 묶지 않습니다.
- `S01`부터 `S08`까지의 시나리오 task는 시나리오 ID를 명시합니다.
- 구체 시나리오 task를 만들기 전에는 해당 시나리오의 제목, 진행 시간, 주요 구역, 시작 트리거, 평범한 업무, 수첩 규칙, 이상 현상, 클리어·실패 조건, 연출, 보상·단서가 승인된 기획으로 제공되어야 합니다.
- 상세 기획이 없는 시나리오 내용은 에이전트가 임의로 채우지 않습니다. 먼저 기획 입력이 필요하다고 알립니다.
- S01 수직 조각에서 검증되지 않은 구조를 S02~S08 공통 구조로 미리 확정하지 않습니다.

## 파일명 규칙

- task 문서 파일명은 `{단계 번호}_{영문 설명}.md` 형식을 사용합니다. 예: `01-2_first_person_movement.md`.
- 단계 번호는 `docs/PLANS.md` 작업리스트의 단계 번호와 동일하게 맞춥니다.
- 영문 설명은 소문자와 언더스코어만 사용하고 띄어쓰기와 한글은 사용하지 않습니다.
- 특정 시나리오 task는 영문 설명에 `s01`처럼 소문자 시나리오 ID를 포함할 수 있습니다.
- 문서 안의 제목은 한글로 작성해도 됩니다.

## 작성 시점별 규칙

### 구현 전

- `구현 항목`에는 현재 task에서 달성해야 하는 결과만 적습니다.
- `범위 밖`에는 이번 task에서 일부러 다루지 않을 항목을 적습니다.
- `사전 전제`에는 이전 단계 산출물이 필요할 때만 실제 전제 대상을 적습니다.
- `수동 작업`과 `결과 확인`은 실제 코드 구현 전에는 구체 내용을 작성하지 않습니다.
- 실제 이름을 알 수 없는 파일명, Actor명, Blueprint명, 위젯명, 맵명, 입력명, 버튼 텍스트, 안내 문구를 추측해서 구체화하지 않습니다.
- 요청에 기존 요소 이름이 명시되어 있으면 프로젝트 코드와 자산 구성을 확인해 실제 존재 여부를 검토한 뒤 구현 항목을 작성합니다.
- Aeterna 기획 기준에 영향을 주는 요청이면 task 초안 작성 전에 영향 범위를 사용자에게 알립니다.

### 구현 후

- 갱신은 실제 추가된 파일명, Actor명, Blueprint명, 맵명, 입력명, 위젯명 같은 구현 결과를 기준으로 합니다.
- 완료된 `구현 항목`과 `에이전트 확인` 체크박스는 실제 완료 범위만 `[x]`로 갱신합니다.
- `수동 작업`은 사람이 결과를 만들거나 진행시키기 위해 해야 하는 조작을 기준으로 구체화합니다.
- `결과 확인`은 실제 결과가 기대한 상태인지 사람이 확인할 수 있는 항목을 기준으로 구체화합니다.
- 사용자가 수동 작업 또는 결과 확인 완료를 응답하기 전에는 해당 확인 항목을 완료 처리하지 않습니다.
- 진행 중인 task에서 추가 변경이 발생해도 이미 완료된 항목은 유지하고, 새 변경으로 다시 확인해야 하는 항목만 `[ ]`로 둡니다.

## 수동 작업과 결과 확인 공통 규칙

- 두 항목 모두 에이전트가 대신할 수 없어서 사람이 직접 해야 하는 일만 적습니다.
- 두 항목 모두 초보자가 그대로 따라 할 수 있도록 단계별로 구체적으로 적습니다.
- 프로젝트에 변경을 남기는 조작은 `수동 작업`에, 아무것도 바꾸지 않고 실행하거나 보기만 하는 절차는 `결과 확인`에 적습니다.

## 수동 작업 작성 규칙

`수동 작업`에는 사람이 실행 전에 미리 준비해야 하는 항목만 적습니다.

대표적인 예:

- 프로젝트 설정에 직접 입력해야 하는 값
- 사람이 직접 선택하거나 연결해야 하는 모델, 애니메이션, 입력, 경로
- 사용할 참고 에셋 파일 배치
- 수첩 규칙이나 시나리오 데이터의 승인된 문구 입력

포함하지 않을 내용:

- 에디터 실행, 맵 열기, PIE 실행처럼 `결과 확인`에 속하는 절차
- 에이전트가 대신 수행할 코드 수정
- 현재 task와 무관한 다음 단계 준비
- 대상과 방법이 없는 추상 문장

## 결과 확인 작성 규칙

`결과 확인`에는 실행 절차와 함께, 그 결과가 기대한 상태인지 확인하는 항목을 적습니다.

- `수동 작업`에 적은 입력, 연결, 설정 절차를 같은 의미로 반복하지 않습니다.
- 현재 task가 시나리오 흐름을 다룬다면 시나리오 ID, 시작 시간, 시작 위치, 성공·실패 상태를 구분해 확인할 수 있게 적습니다.

사람이 실행하고 눈으로 확인할 수 있는 대표 절차:

- Unreal Editor 실행
- 대상 맵 열기
- PIE 실행
- 이동 또는 상호작용 입력
- 수첩 규칙과 업무 목표 확인
- 이상 현상과 상태 변화 확인
- 실패 후 시간·위치·시나리오 상태 복구 확인
- 클리어 후 경비실 복귀와 다음 슬롯 대기 확인

포함하지 않을 내용:

- 코드 내부 구조 설명
- 구현되지 않은 다음 단계 동작
- 현재 task 범위 밖의 전체 통합 흐름
